Delivered locally on 2026-10-07. The work improves Affiliate Engine around its own purpose; Educator supplied a visual/workflow reference, not copied source or a new product scope.

## What changed

- **Lead generation:** searchable cards/list library, status and purpose filters, five creation families, duplication as draft, pause, per-page results and sharing. Existing sixteen type values stay compatible and are described honestly; quizzes capture answers rather than calculating scores.
- **Editor:** bounded controls and a flexible preview; Content, Form, After signup and Appearance sections; three layouts; image thumbnails; protected-resource cards; question reordering; automatic question identifiers; draft indicators and navigation protection; contextual readiness information.
- **Publication:** migration 10 adds a published snapshot. The new editor saves through dedicated draft routes. Explicit publication validates and replaces the snapshot. Existing active pages are migrated without changing public content. Existing confirmation/download/enrollment snapshots remain intact. Media referenced by both the draft and published page stays protected from deletion.
- **Previews:** phone/tablet/desktop widths and native modal expansion; lead page, acknowledgement, confirmation-email and success simulations; the lead public page and editor share a renderer; no preview submission creates contacts or sends mail. Preview resources remain metadata/disabled controls rather than live download grants. Themes are reflected in previews. Website content has a selected-item draft preview; newsletter HTML previews update after edits using the server sanitizer/renderer.
- **Public experience:** three responsive lead layouts, clearer signup acknowledgement, better card imagery and hierarchy, resource search, bounded upcoming lists with category filtering, dedicated shareable resource pages, and clearer next steps through confirmation and resource delivery.
- **Sharing:** native share when available, copy link, WhatsApp, Facebook, LinkedIn, X and email. Share links use resource pages, not affiliate redirect URLs; offer/upcoming paths include the kind to avoid slug collisions. No embedded third-party social widget is installed. Sharing is performed by the visitor; this work did not post anything externally.
- **SEO:** production HTML contains titles, descriptions, canonical URLs, Open Graph and Twitter metadata before JavaScript runs, plus bounded noscript content. Sitemap includes active resources and published lead pages. Robots rules/private no-index headers exclude administration, APIs and token/action endpoints. Metadata does not repeat private confirmation tokens. Missing public pages return HTTP 404 in production. Vite remains a development renderer; deployed production HTML is the crawler-ready version.
- **Disclosure/storage:** owner-configured affiliate disclosure appears beside affiliate actions, including post-confirmation recommendations; links use sponsored attributes. An accurate necessary-storage notice offers remembering it or continuing without remembering. The privacy page includes a cookie inventory. No optional advertising/browser-analytics integration was added. Existing server acquisition/click logs and optional email tracking are explicitly distinguished from browser analytics.
- **Admin usability:** compact content libraries, bounded forms, contextual create/public-preview actions, smaller dashboard groups, subscriber filters with an advanced section, a native detail drawer that preserves table position, readable acquisition fields, and sequence timelines with days/hours/minutes while retaining offsets from confirmation.
- **Performance:** separate public/admin bundles and lazy-loaded lead studio, lazy library images, no new UI dependencies, no heavy chart/animation package, and debounced email preview rendering.

## Local review and normal delivery

Use `npm run preview` from the root to review at `http://127.0.0.1:5173/` and `/admin/lead-pages`. It uses existing local data and performs normal migrations, but neither email worker starts. Preview is not a disposable database: ordinary live forms/admin saves still persist records, and queued messages wait.

Stop the review process before running `npm run dev` for normal development with workers enabled. Normal `npm start` in production also enables workers unless `PREVIEW_ONLY=true` is explicitly set. Do not run standalone workers during review if outgoing mail must stay paused.

Production sharing needs a reachable HTTPS deployment and the correct Settings > Domains public URL and SITE_URL. Social services cannot fetch thumbnails from a visitor's localhost; their caching is outside this application's control.
