# Final delivery report

Latest update: [public/admin experience delivery](docs/UX-DELIVERY.md), migration 10, 65 passing backend tests, production builds and SEO HTTP checks. Review mode is available through `npm run preview` with outgoing workers disabled.

The ten-phase V1 implementation is complete locally. It is a single-owner engine; public launch still requires the owner's domain, SMTP configuration and content. See [README](README.md), [operations guide](docs/OPERATIONS.md) and [verification](docs/VERIFICATION.md).

1. **Built:** Secure administration; configurable public affiliate website; validated media library; subscriber consent and confirmation; tags and AND/OR segments; reusable rich/HTML newsletters; immediate/scheduled manual campaigns; sixteen lead-page presets with questions; protected downloads; confirmation-triggered email sequences; date-filtered analytics and safe paginated logs.
2. **Structure:** `client/` contains React/TypeScript/Vite/Tailwind admin and public views. `server/src/` contains Express routes, SQLite migrations, auth/security, settings, content/media, contacts, mail, marketing, lead-pages, automations and analytics. `shared/` contains shared TypeScript contracts. `server/test/` contains integration/regression tests. `data/` and `uploads/` hold persistent local state.
3. **Entities:** Nine append-only migrations create admin, admin_sessions, settings, events, media, media_usage, content_items, website_sections, contacts, tags, contact_tags, lead_submissions, contact_tokens, transactional_outbox, worker_heartbeats, newsletters, segments, campaigns, email_queue, email_links, lead_pages, download_tokens, automations, automation_steps and automation_enrollments. Foreign keys, unique constraints and indexes protect lifecycle and queue invariants.
4. **Public routes:** `/`, `/p/:slug`, `/privacy`, `/terms`, `/affiliate-disclosure`, `/confirm/:token`, `/unsubscribe/:token`, `/unsubscribe`; `/api/public/site`, `/countries`, `/subscribe`, `/resend`, `/confirm/:token`, `/unsubscribe/:token`; `/media/:id`, `/download/:token`, `/go/:slug`, `/go/upcoming/:slug`, `/email/open/:token.gif`, `/email/click/:token/:ordinal`. API paths are relative to `/api/public` where listed together. Full route table is in README.
5. **Admin routes:** `/admin` dashboard; `/admin/newsletters`, `/campaigns`, `/automations`, `/leads`, `/segments`, `/lead-pages`, `/content`, `/uploads`, `/settings`, `/logs` under `/admin`. Protected APIs are under `/api/admin`; analytics uses `/analytics`, `/activity-log`, `/delivery-log`. Auth session/login/logout/password APIs are under `/api/auth`. No public account creation or default password.
6. **Email sending:** Nodemailer uses owner-configured SMTP with TLS/STARTTLS and encrypted credentials. Rendered newsletters are sanitized, personalized and delivered as HTML plus plain text with mandatory identity/unsubscribe footer. Explicit test recipients are separate from subscriber delivery. Queue results record SMTP acceptance or sanitized errors; acceptance does not prove inbox placement.
7. **Worker/scheduler:** The API automatically starts transactional and marketing workers. Separate `worker:transactional` and `worker:marketing` commands are also available. SQLite durable claims and uniqueness prevent duplicate jobs; marketing claims share a two-second pace. Proven pre-send connection failures may retry. Ambiguous outcomes/interrupted processing are failed rather than silently resent. Campaign scheduling and automation run independently of an open browser. Graceful shutdown stops new HTTP work and waits for workers before closing SQLite.
8. **Double opt-in:** Explicit consent creates a pending contact and immutable source/consent submission. A hashed, expiring confirmation token is sent using an encrypted transactional payload. GET previews; POST confirms. Confirmation is idempotent and assigns source tags. Lead pages always require confirmation, even if ordinary newsletter single opt-in is enabled. Unsubscribe and suppression are rechecked before marketing delivery.
9. **Automation:** An ordered sequence of ready newsletters uses minute offsets from confirmation. Enrollment is unique per contact/sequence and snapshots content, due times and tag actions. Pausing holds future delivery and actions; resume paces overdue work. Tag actions assign tags once when a due eligible step starts, before SMTP acceptance. Existing enrollments retain original snapshots after edits. Page inactivity prevents new signups; it does not revoke already-promised resources or sequences. Unsubscribe cancels enrollment permanently. Private resource URLs are expiring grants and bypass click tracking.
10. **Segmentation:** Parameterized AND/OR rules cover status, country, continent, original source, tags, dates and campaign/open/click engagement. Preview shows matching and eligible totals. Launch snapshots segment rules; due resolution uses current contacts. Confirmed status is mandatory regardless of OR rules or explicit selection.
11. **Affiliate tracking:** Active offers redirect through `/go` and store outbound click events when enabled. Direct affiliate destinations are omitted from public content APIs. Email clicks use stored destinations and hashed tracking tokens; opens are optional pixels. Analytics shows event counts and unique per-message rates among messages sent with the corresponding tracking enabled. Email scanners/proxies affect these observations; they do not represent verified purchases.
12. **Run:** Node 24.13+ within Node 24; `npm install`, copy `.env.example` only for a fresh install, `npm run security:setup`, `npm run db:migrate`, `npm run admin:setup`, `npm run dev`. Open `http://127.0.0.1:5173/admin/login`. Existing installations preserve `.env`, key, database and uploads. Production: `npm run build`, set `NODE_ENV=production`, `npm start` behind an HTTPS reverse proxy. See operations guide before deployment.
13. **Environment:** `NODE_ENV`, `HOST`, `PORT`, `SITE_URL`, `TIMEZONE`, `DATABASE_PATH`, `UPLOAD_DIR`, `SETTINGS_ENCRYPTION_KEY`, `SESSION_HOURS`, `TRUST_PROXY`; documented defaults in `.env.example` and README. `SITE_URL` is a root HTTP(S) origin and the trusted admin origin. Public Domains URL controls generated subscriber links. SMTP settings are stored in SQLite, not environment variables. Never replace a working encryption key or commit secrets.
14. **Deferred V2:** Customer accounts/multi-tenancy, billing/payments, CRM, visual automation canvas, AI generation, social scheduling, advanced attribution, automatic bounce/complaint webhooks, large-scale bulk-mail infrastructure and distributed scheduling. No external deployment or paid services were provisioned.
15. **Known limits:** Browser visual inspection was unavailable; responsive code and build were checked, but manual desktop/mobile/keyboard review remains a launch task. Real provider inbox tests and sender-domain setup require owner credentials/domain. SQLite is experimental in Node 24. Local signature validation is not antivirus scanning. Tracking is approximate; suppression/bounces/complaints are manual until provider integration. Failed-job cards use job creation dates; accepted sends use sent dates; lead cards use creation cohorts with current status. All-time daily chart covers the latest 30 days. Local uploads/database/key require coordinated backup. SQLite and one-host local storage are intended for modest single-owner traffic.
16. **Next scaling priorities:** Observe queue latency/failures and SMTP provider limits; add provider bounce/complaint handling and monitoring; automate verified backups and restore drills; add upload malware scanning; only after measured need move media to protected object storage and queues/database to managed services. Preserve consent, snapshot, unsubscribe and delivery-outcome invariants during migration.
